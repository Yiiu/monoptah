# 实施与验证步骤

1. **建立基线。** 创建与报告样本规模相同的脱敏长会话，覆盖多个长工具输出、推理行和 Markdown。记录点击、设置恢复、读取历史、准备布局和首屏出现的时间点，以及重开前后的缓存状态。分别测量冷打开、淘汰后切回、命中缓存、停止生成后滚动和生成中滚动。发布构建上复用 `scripts/perf/frame-run.sh` 的帧统计与 `MODE=scroll` 路径。
2. **消掉重复读取。** 检查 `Store::agent_settings` 所有调用方。为会话的打开、重新加载路径接入轻量设置加载。核对同一数据上轮次信息、账号、操作模式、Goal 和保存版本的行为，并验证存储读取计数。重点核对 `crates/monocode-core/src/store/shared.rs` 和 `crates/monocode-gpui/src/conversation/history.rs`。
3. **接入首屏范围和锚点。** 从最新轮次或记住的阅读位置加载。复用 `transcript/history.rs` 的窗口、向上分页和位置恢复，补齐普通会话在缓存丢失、搜索及异步切换时的行为。验证可见行与绝对行号的映射，以及继续发送后的新消息。
4. **处理已确认的滚动开销。** 分别在短会话和长会话跑同样的滚动轨迹。根据基线先处理目录扫描或过度测量，改动后比较主线程 CPU、帧耗时和阅读锚点。用独立提交隔离加载链与展示层改动，便于定位和回退。
5. **复核验收。** 对照 [PRD](prd.md) 中 R1–R5，记录性能结果、回归测试和仍存在的瓶颈。性能回放使用独立开发数据。

## 本地检查

从仓库根目录运行格式与静态检查，并按实际触及的模块定向测试。

```sh
cargo fmt --manifest-path crates/monocode-gpui/Cargo.toml --all --check
cd crates/monocode-gpui
cargo nclippy -p monocode-core -p monocode-gpui --all-targets -- -D warnings
cargo ntest -p monocode-core store::native_chunks::tests
cargo ntest -p monocode-gpui transcript::history::tests -- --test-threads=1
cargo ntest -p monocode-gpui shell::session_loading::tests -- --test-threads=1
```

实现中如触及普通会话发送和编辑入口，追加该入口的定向回归。合并前使用仓库的 Native 批次质量门。

## 本轮验证

- macOS 上最终 GPUI 定向套件通过 236 项，覆盖普通会话首屏、分页锚点、旧锚点恢复、预览交接、搜索、发送和编辑。代码格式、差异检查及 core 和 GPUI 的 Clippy 均通过。
- 最终存储套件通过 503 项，覆盖旧格式角色、轮次元数据、稀疏块编号、旧锚点就近读取和存储兼容行为。

### macOS 发布构建对照

基线为 `native-v0.57.0`（`22714cf7`），优化版为同一基线加上本任务的代码改动。两版在同一台 Apple Silicon Mac 上以相同的 arm64 release 配置构建并运行。基准从正常的会话打开路径触发切换，每种场景测量 20 次，记录到首个含历史消息的窗口帧。未缓存打开指进程内没有该会话视图，操作系统文件缓存已预热。淘汰切回经过非活动历史缓存预算，缓存命中场景为基准保留大历史后测量。

从本地数据库以只读方式提取三条真实历史，测试在私有临时数据库中进行。报告使用匿名样本名和聚合统计。真实样本只测切换与停止生成后的滚动，生成用例使用独立的合成历史和本地模拟回复。
