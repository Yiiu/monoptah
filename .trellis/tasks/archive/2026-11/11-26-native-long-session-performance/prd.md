# 优化 Native 长会话切换与滚动性能

## 目标

降低本地普通会话从点击到看到消息的延迟，并减少长会话滚动时的掉帧和 CPU 开销。用户切回正在阅读的会话时，第一屏恢复到离开前的位置。

## 已有证据

- 在 Native 0.57.0 只读检查了一条用户报告卡顿的本地 Claude 会话。它已采用 v1 分块存储，有 27 个提示词起点、3,200 个存储块和 4,569 行。全段行数据 29.34 MiB，最近 10 轮包含 333 行、2.54 MiB。样本仅保留聚合统计。
- 首次打开和缓存淘汰后切回都调用 `agent_settings` 和 `load`。前者通过 `shared_agent` 重建所有历史块来恢复轮次元数据，后者再次读取完整消息行。按样本存储量，两步共处理约 87 MiB 的逻辑数据，尚未计入解析和布局。见 `crates/monocode-core/src/store/shared.rs:906`、`crates/monocode-gpui/src/conversation.rs:944` 和 `crates/monocode-gpui/src/conversation/history.rs:157`。
- 非活动历史共用 32 MiB 估算预算。符合淘汰条件的空闲长会话容易在返回后重走加载流程。见 `crates/monocode-gpui/src/shell/session_loading.rs:66`。
- 观察到 Native 进程 CPU 一度约 85%。非动作同步的短采样抓到聊天列表布局、行高测量和消息行重建。消息目录会在滚动后从历史提示词开头扫描，即使目录已隐藏。滚动各阶段的占比有待对照采样。见 `crates/monocode-gpui/src/transcript/outline.rs:90`。

## 需求

| 编号 | 用户可观察行为 |
| --- | --- |
| R1 | 打开或切回长会话时，立即看到选中标签和可编辑输入框，尽快看到首屏消息。设置恢复去掉对整段历史的额外读取。 |
| R2 | 首次打开或离开前正在跟随底部时，首屏从最近一页显示。切回正在阅读旧消息的会话时，首屏直接恢复原消息与行内偏移，缓存被淘汰也一样。 |
| R3 | 向上加载旧消息时，视口内的锚点保持原位。收到新回复时，跟随底部的会话继续跟随，正在翻阅的会话留在原处。搜索可以直接定位旧消息。 |
| R4 | 发送、编辑、重试、草稿和排队保留原有语义，历史轮次归属、行号与写入版本检查保持正确。 |
| R5 | 单独验证停止生成后滚动、生成中滚动和冷切换。通过采样确认滚动热点并处理已确认的开销。 |

## 验收

- **R1** 使用同一台 Mac、同一发布构建配置和同一个脱敏长会话样本前后对照。建议目标为冷打开点击到首屏可见的 P95 降低至少 50%，缓存命中切回的 P95 小于 100 ms。读取计数证明打开和重新加载时设置恢复不再重建全部块。
- **R2–R3** 覆盖连续上翻、缓存淘汰后切回、快速切换、搜索跳转、图片或代码块重排，以及在阅读时收到回复。检查锚点消息与视口位置，首屏禁止闪现底部再回跳。
- **R4** 覆盖 v1、v2、旧 blob 数据及写入版本冲突。校验历史前缀完整、发送和编辑位置正确，并复跑受影响的 Mono 历史测试。
- **R5** 录制停止生成和生成中两组滚动样本，记录 P95 帧耗时、超帧预算帧数和主线程 CPU。先取得基线，再以相同滚动速度和内容评估改动。

## 范围

本地 Native 普通会话的首屏准备、非活动历史恢复和滚动。云端会话协议、TUI、React/Tauri 界面及批量转换历史存储均在范围外。

窗口空闲重绘、编辑器 Git 轮询、图形资源和代理内存由 Native 资源占用任务跟踪。
