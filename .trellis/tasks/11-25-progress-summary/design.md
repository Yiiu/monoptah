# 第 2b 期技术设计

## 摘要

- 用第 1 期状态缓存的真实回合结束事件触发摘要。数据库在 Native 侧车的 `session_activity` 表中保存最新完成回合的摘要，桌面共享表结构保持兼容。
- 完成状态和保底摘要一起写入。快速模型工作在后台，沿用背景文本模型的账户和选择规则，使用隔离的纯文本请求。摘要输入只取最后一段有界的自然语言回复。
- 结果按会话、回合结束时间匹配。上一回合的迟到结果、已删除会话的结果和取消任务的结果均不应用。模型失败或无可用模型时保留本地摘要。
- Tree 使用 `Shell::progress_summary(id)`。终端或无可用正文的会话保留表达完成、失败或停止的一行文字。

## 归档

- 手动归档继续使用会话菜单和已有的归档行为。
- 设置中的工作树清理成功后，归档该工作树里已结束、没有待发草稿的会话。保留回合内容、已读标记和摘要。
- 定时由本地 Git 数据确认工作树属于该项目。分支合并要求工作树干净，且当前提交已经进入工作树基准分支或项目主分支。空分支不产生合并证据。显式关联的 GitHub PR 也可提供 squash 或 rebase 证据，要求合并状态、当前分支、当前提交和基准分支完全匹配。清理使用设置中成功移除工作树的记录。
- 自动归档只在 Tree 模式运行，并只作用于证据直接涵盖的会话。归档状态写入后保存证据，避免用户恢复的会话因同一事件再次归档。检查期间开始工作或改变工作树的会话在应用前重新检查。
