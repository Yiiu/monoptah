# Tree 动效遗留问题

Parent: `11-25-agent-overview`。开工前先读父任务的 `handoff.md`。**必须等 `11-26-tree-polish` 合回主分支之后再开始**，因为两个任务改的是同一批文件。问题来源：`audit-tree-summary.md` 中的 (a)(b)(c)。

## Goal

未读完成行的"延后收起"和项目拖拽，在所有入口和边界情况下都表现正确，不出现补播动画、卡住不收起或位置错乱。

## Requirements

### R1 切换布局不会补播收起动画（a）
- 离开 Tree 布局时，立即结算所有"延后收起"的行，不播放动画。结算的时机放在 `set_navigation_layout` 里。另外有三处直接修改 `classic_layout` 的地方也要处理：`classic_sidebar.rs:982`、`layout.rs:1154`、`quick_open.rs:139`。建议统一改成调用 `set_navigation_layout`；做不到的话，至少要在这三处补上结算。
- 回到 Tree 布局时，这些行直接显示为已读的样子。

### R2 打开应用页时也会收起（b）
- "这一行还在被查看"的判定，从只看 `workspace.active` 改为：这个会话正显示在屏幕上，并且当前没有打开任何应用页（Inbox、Today、Notes、Settings、Automations、Contributors），也没有处于 Mono 对话里。
- 一旦不再被查看，就按原来的 200ms 动画收起。

### R3 拖拽的边界情况（c）
- 标题行已经滚出可视区顶部的项目块，也要参与让位计算。数据可以从列表测量值或行模型中推算，不能直接排除这类项目块。
- 拖拽过程中滚动列表时，各项目块的让位偏移量要按新的滚动位置重新计算。也可以选择在拖拽期间自动滚动，并且只能由拖拽本身触发滚动。两种方案选一种，写进 design。
- 拖到列表顶端或底端附近时自动滚动，速度与距离边缘的远近成正比。
- 松手的那一帧，被拖项目块的浮起底板不能缺失。如果无法稳定复现，在测试中断言松手那一帧仍然存在底板的绘制边界即可。

## Acceptance Criteria

- [ ] Tree → Classic → 切换会话 → Tree：之前的行不会补播动画，直接显示为已读（测试）。
- [ ] 打开一个未读完成的会话后再打开 Inbox：这一行收起（测试）。
- [ ] 标题在可视区上方的项目块，在拖拽时会让位（测试）。
- [ ] 拖拽过程中滚动列表 N 像素，项目块的偏移量随之修正，松手后的顺序符合指针位置（测试）。
- [ ] 拖到边缘时会自动滚动（测试，或实机录屏）。
- [ ] 开启"减少动态效果"时，以上所有变化都立即完成。
- [ ] Classic 布局的拖拽不受影响：阈值 5px、时长 160ms（现有测试保持通过）。
