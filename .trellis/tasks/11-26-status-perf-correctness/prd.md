# 状态核心：性能与正确性

Parent: `11-25-agent-overview`。开工前先读父任务的 `handoff.md`。本任务的问题来源于审计报告
`11-25-agent-overview/research/audit-status-mono.md`（下文"第 N 项"指该报告的编号），以及
`audit-tree-summary.md` 中关于进展摘要的部分。

## Goal

状态显示要准确，但不能拖慢应用：只有状态发生变化时才做相应的工作，应用空闲时没有持续的开销。

## Requirements

### R1 状态刷新节流（第 3 项）
- 现状：每批流式输出（约每 16ms 一次）都会刷新状态，每次都要扫描 transcript、解析最后一次工具调用的 JSON。
- 要求：活动状态的切换（例如 Running → Done、进入 NeedsYou）仍然**立即**生效。只有"当前步骤"这段文字需要节流，最多每 15 秒刷新一次，或者在最后一次工具调用变化时刷新。
- 解析工作只在工具调用的 id 变化时执行，不能每帧都做。

### R2 计时器只在需要时运行（第 4、5 项）
- Mono 时钟（每 10 秒一次）只在确实有巡检到期时，才为对应的 Mono 构建会话视图；没有任何巡检到期时，几乎不做任何工作。
- 额度等待期间，计时器按"距离恢复时间还剩多久"来安排下一次唤醒：剩余时间较长时按分钟级刷新显示，接近恢复时间时再提高刷新频率。不能在整个等待期间（可能长达数小时）一直保持 15 秒一次。
- Tree 布局里每 75 秒一次的 git worktree 检查：窗口不在前台时暂停。

### R3 终端会话不误报"No update in 30m"（第 1 项）
- 终端会话本身不上报"最后一次事件"的时间。改为把终端输出活动当作事件来源（终端有输出就更新最后活动时间）。如果拿不到输出活动，终端会话就不参与 stale 判定。

### R4 旧版 Mono 选项卡不误触发 Needs you（第 2 项）
- 升级前产生、之后用户已经打字回复过（即选项卡后面已经有用户消息）的旧选项卡，视为已回答。
- 只有升级后产生、并且确实还没回答的卡片，才计入 NeedsYou。

### R5 Mono 工具返回新的状态（第 12 项）
- Mono 的 sessions 工具（`shell/app_commands.rs:486`）改为根据统一状态返回 busy，与侧边栏保持一致。只挂着 dev server 的会话不再返回 busy。

### R6 迁移不会重新把所有会话标为已读（第 21 项）
- `session_activity` 表被删除或损坏后重建时，不能再次把所有会话标为已读。可以用一个单独的"已完成迁移"标记来判断，也可以只在第一次建表时补数据。
- 重建后要刷新内存中的状态，不能出现内存和数据库不一致的情况。

### R7 限制增长（第 10、20 项）
- 选项卡的选项数量设一个合理上限（例如 12 个）。超出时拒绝创建，并返回清楚的错误给 Mono，不能静默截断。
- `Mono.decision_cards` 只保留最近的若干条，或者在卡片被回答、所属会话被归档后清理。
- `heartbeat.json` 里的巡检快照不包含已归档的会话。

### R8 进展摘要不被并发上限吞掉（audit-tree 第 3 项）
- 同时生成摘要的数量上限仍为 4。超出的任务排队等待，不能直接退回兜底文字。
- 远程会话、终端会话，以及失败或被停止的轮次，继续使用兜底文字（这是有意的设计，保持不变）。

## Acceptance Criteria

- [ ] 一个持续流式输出的会话：状态刷新带来的解析次数和工具调用的次数相当，而不是和帧数相当（用测试或计数器证明）。
- [ ] 没有任何 Mono 巡检到期时，Mono 时钟不会为任何 Mono 构建会话视图（测试）。
- [ ] 额度等待超过 1 小时的会话，等待期间计时器的唤醒次数是分钟级的，不是 15 秒级的（测试）。
- [ ] 一个输出持续超过 30 分钟的终端会话，不会显示 "No update in 30m"（测试）。
- [ ] 升级前已经被打字回复过的旧选项卡，不会让 Mono 显示 Needs you（测试）。
- [ ] Mono sessions 工具对只挂着 dev server 的会话返回 `busy: false`（测试）。
- [ ] 删除 `session_activity` 表后重启：原本未读的会话仍然保持未读（测试）。
- [ ] 超出上限的选项卡会被拒绝，Mono 能收到错误；`decision_cards` 和巡检快照不会无限增长（测试）。
- [ ] 同时完成 6 个轮次时，6 个摘要最终全部由模型生成（测试）。
- [ ] 不新增设置项；Classic 和 Focused 的行为不变。
